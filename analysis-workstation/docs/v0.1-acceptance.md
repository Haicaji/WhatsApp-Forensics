# Analysis Workstation v0.1 验收记录

本记录只使用仓库内合成 Evidence Bag，不包含真实 WhatsApp 账号、联系人或聊天内容。

| 需求 | 实现位置 | 可复核证据 |
|---|---|---|
| 独立 pnpm/Electron/React/TypeScript 工程 | `package.json`、`pnpm-workspace.yaml`、`apps/desktop` | `pnpm typecheck`、`pnpm build` |
| Rust USB Provisioner 接入 GUI | `workstation-core/provisioning.ts`、固定 IPC、创建 U 盘弹窗 | 纵向测试实际启动 release EXE 并解析签名收据 |
| 创建勘察员、密钥和签名任务 | Rust Provisioner + `WorkstationCatalog` | 完整 `config/`、`assignments/`、登记公钥指纹；同 operator/key 不允许替换公钥 |
| 保留 U 盘原有内容 | 只创建固定 `Field Collector/`，随机 staging 后原子晋升 | 测试哨兵文件逐字节保持，现有同名目录拒绝覆盖 |
| 自动接收并匹配案件 | `intakeUsbAutomatically` + 案件列表入口 | 按已验证 assignment 自动路由；第二次接收返回 `already_imported` |
| 无效或不可信包拒绝 | 独立 `waeb-verify.exe` 两阶段验证 | 未登记签名者、单字节篡改测试均在归档前失败 |
| 每案 SQLite 与 FTS5 | `evidence-repository/src/node.ts` | 3 条消息导入，中文“合成的测试消息”命中 1 条；全局 DB 无正文 |
| 稳定 EvidenceRepository | `evidence-repository/src/index.ts` | 案件摘要、来源、聊天、消息、上下文、搜索、完整性统一接口 |
| 案件/聊天/消息/搜索/完整性 UI | `apps/desktop/src/renderer` | Electron 43 真实窗口 CDP 点击与截图，渲染异常为 0 |
| Electron 安全边界 | `main/index.ts`、单文件 preload、固定 IPC | sandbox/context isolation/no Node integration；CSP；权限、导航、新窗口、webview 全拒绝 |

## 自动化场景

最终测试汇总为 40 项通过（15 项 TypeScript/Node，25 项 Rust），0 失败、0 跳过。

- 领域 Schema 与游标输入校验。
- 每案 SQLite 建库、分页、中文 FTS5 trigram、消息上下文和完整性摘要。
- 可信合成包首次导入与重复幂等导入。
- 未登记签名公钥拒绝且不创建归档。
- 已登记签名者的 Evidence Bag 被修改一个字节后，独立校验器拒绝。
- 同一勘察员 ID/密钥 ID 的公钥替换攻击被拒绝。
- U 盘内多个 sealed 包扫描、按任务自动匹配案件、重复接收幂等。
- U 盘原文件保留、固定目录生成、配置/任务/密钥文件完整。

## 真实桌面验收

在 Electron 43.3.0 中完成以下操作：

1. 初始化实验室信任身份。
2. 创建空案件。
3. 打开含 1 个可信来源、1 个聊天、3 条消息的合成案件。
4. 浏览聊天与消息。
5. 输入中文连续子串并得到唯一结果。
6. 查看签名指纹、manifest root、历史/媒体范围及两条取证限制。
7. 用最终单文件 main/preload 构建再次启动，确认“自动接收取证 U 盘”入口存在。
